# **PS-02: DPDP-Ready Privacy Gateway for Enterprise LLMs** 

**EVENT DURATION DATES** Code Commit, BIET Davangere 24-Hour On-Site Hackathon 12–13 November 2026 

## **1. PROBLEM OVERVIEW** 

Enterprises increasingly use Large Language Models (LLMs) to process sensitive documents such as loan applications, KYC documents, customer support tickets and insurance claims. 

These documents frequently contain Personally Identifiable Information (PII), including names, addresses, Aadhaar numbers, PAN numbers, GSTIN, passport details and other sensitive personal information. 

Sending such information directly to external AI services creates privacy and data protection risks. 

The Digital Personal Data Protection (DPDP) Act, 2023 and DPDP Rules, 2025 establish requirements around personal data processing, security safeguards and accountability. 

The challenge is to enable enterprises to use powerful external LLMs without exposing original personal information. 

## **2. PROBLEM STATEMENT** 

Build a DPDP-ready privacy gateway that acts as an intermediary between internal enterprise applications and external Large Language Models. 

The gateway must detect sensitive personal information in incoming documents, replace the detected information with consistent typed placeholders and send only sanitized text to the external LLM. 

For example: 

##### **Original Input** 

“My name is Rahul Sharma. My Aadhaar number is 1234-5678-9012 and my PAN is ABCDE1234F.” 

##### **Sanitized Output** 

“My name is <PERSON_1>. My Aadhaar number is <AADHAAR_1> and my PAN is <PAN_1>.” 

The gateway must use a local PII detection layer based on Microsoft Presidio with India-specific recognizers, along with a local Named Entity Recognition (NER) model or Small Language Model (SLM) to identify names and addresses in Indian English and code-mixed text.

Only sanitized text must be forwarded to the external LLM for summarization or information extraction. 

After receiving the LLM response, the gateway must locally reinsert the original values using the placeholder mapping. 

The system must maintain an audit record for every request, including detected entity types, the exact sanitized payload sent outside the organization and the external model that received it. 

The solution must prove that no raw PII is leaked in outbound requests and that placeholder reinsertion remains correct even when the LLM paraphrases, reorders or drops placeholders. 

## **3. MUST-HAVE REQUIREMENTS (MANDATORY)** 

All the following requirements must be implemented and demonstrated. 

## **3.1 PII Detection Engine** 

I Implement a local PII detection layer using Microsoft Presidio. 

I Enable India-specific recognizers. 

I Detect the following Indian identity information: 

   - Aadhaar Number 

   - PAN Number 

   - GSTIN 

   - Voter ID 

   - Passport Number 

- I Use a local NER model or Small Language Model (SLM) to detect personal names and addresses. 

- I Support Indian English and code-mixed text. 

I Identify and classify detected PII entities correctly. 

## **3.2 PII Masking and Consistent Tokenization** 

I Replace detected PII values with consistent typed placeholders. 

I Use placeholders such as: 

   - <PERSON_1> 

   - <AADHAAR_1> 

   - <PAN_1> 

   - <GSTIN_1> 

   - <ADDRESS_1> 

   - <PASSPORT_1> 

   - <VOTER_ID_1> 

- I Ensure that repeated occurrences of the same entity use consistent placeholders within the request. 

- I Maintain a secure local mapping between placeholders and original values. 

- I Ensure that original personal information is not included in the sanitized outbound payload. 

## **3.3 Privacy Gateway API** 

Build a gateway API implementing the following stages: 

**Stage 1 – Detect:** Identify sensitive personal information in the incoming document. 

**Stage 2 – Mask:** Replace detected PII with consistent typed placeholders. 

**Stage 3 – Forward:** Send only sanitized text to a configurable external LLM backend.

**Stage 4 – Reinsert:** Restore original values locally using the placeholder mapping. 

The gateway must support a pluggable LLM backend so different external LLM providers can be integrated. 

## **3.4 External LLM Integration** 

I Integrate at least one external LLM API. 

- I Send only sanitized text to the external model. 

- I Support summarization or information extraction tasks. 

- I Ensure that original PII values never appear in outbound requests. 

- I Capture the exact payload sent to the external LLM for verification and auditing. 

## **3.5 Local Placeholder Reinsertion** 

- I Reinsert original values into the LLM response locally. 

- I Maintain correct mappings between placeholders and original values. 

- I Handle responses where the LLM paraphrases or reorders placeholder-containing content. 

- I Handle missing or dropped placeholders safely. 

- I Prevent incorrect replacement of one person's information with another person's information. 

## **3.6 Demo Interface** 

Build a working demonstration interface showing three sections side by side: 

#### **A. Original Input** 

I Display the original document containing personal information. 

#### **B. Outbound Sanitized Payload** 

I Display the exact sanitized text sent to the external LLM. 

- I Show the detected entity types and their placeholders. 

#### **C. Final Response** 

I Display the LLM-generated response after local placeholder reinsertion. 

The interface must make it easy to verify that raw PII is not exposed to the external model.
